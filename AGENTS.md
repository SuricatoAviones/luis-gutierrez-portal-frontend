# AGENTS.md — luis-gutierrez-portal

## Package manager

- Use **pnpm** (not npm). `pnpm-lock.yaml` is the source of truth; `package-lock.json` is stale.
- `pnpm install` to set up.

## Commands

| Command | Purpose |
|---------|---------|
| `pnpm dev` | Start dev server |
| `pnpm check` | Astro diagnostics + TypeScript checking (the only "lint+typecheck" step) |
| `pnpm build` | Build static site to `dist/` |
| `pnpm preview` | Serve `dist/` locally |

No test runner, no linter, no formatter configured.

## CMS & build

- WordPress headless CMS — content (posts, projects, skills, experience) fetched at **build time** via `src/lib/wordpress.ts`.
- After editing content in WordPress, run `pnpm build` and redeploy to reflect changes.
- `/blog/post` is a client-side fallback (noindex) for posts published between deploys.

## Env vars

| Var | Scope | Required |
|-----|-------|----------|
| `WP_API_URL` | Build-time only | Yes |
| `PUBLIC_FORMSPREE_FORM_ID` | Browser (Formspree) | No (contact form) |

Copy `.env.example` to `.env`.

## Project quirks

- `@/*` maps to `./src/*` (configured in `tsconfig.json`).
- `.astro/` is auto-generated by Astro — do not edit.
- Sitemap excludes `/404` and `/blog/post`.
- `skills-lock.json` registers agent auto-skills (accessibility, astro, seo, tailwind-css-patterns, etc.) — relevant when asked to improve those areas.
- `dist/` is gitignored build output.
- Tailwind CSS 4 is integrated via `@tailwindcss/vite` plugin (not PostCSS config).
- Site deploys to **https://luisangelgutierrez.com** (likely via cPanel — see `docs/despliegue-cpanel.md`).
